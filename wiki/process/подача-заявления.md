# Подача заявления в Архитектурную комиссию

Практическая инструкция по ЛК СтроимПросто. Детали полей — в `raw/stroimprosto-arh.md`. Этапы и состав — [этапы-согласования](этапы-согласования.md), [требования-к-материалам](../concepts/требования-к-материалам.md).

## Подготовка

1. ЭЦП организации / уполномоченного лица.
2. Статус **«застройщик»** в ЛК СтроимПросто (вход от имени организации через mos.ru / СУДИР; письмо на `grad@mos.ru` со скрином профиля, ИНН и подтверждением деятельности).
3. Выбор [этапа](этапы-согласования.md): концепция / НПМ / ВПМ / иное.
4. Услуга: **«Заявление в Архитектурную комиссию ДГП»** → отслеживание в «Услуги и заявки».

## Два сценария формы

### Вариант A. Мэр уже одобрил ВПМ и ЦИМ, свидетельства ещё нет

Поле «Проект согласован Мэром Москвы» = **Да**. Дальше — реквизиты письма ДГП (МКА) об одобрении, загрузка уже согласованных моделей (ВПМ, НПМ, ссылка на проверку IFC). После 30.09.2026 для новых дел этот сценарий реже нужен: свидетельство уходит проактивно. Имеет смысл для «хвостов» переходного периода.

### Вариант B. Первичная подача / корректировка / изменение свидетельства

«Проект согласован Мэром» = **Нет**. Затем вид материалов (концепция, НПМ, ВПМ…).

**Роль организации:**

- **Заинтересованное лицо** — застройщик, на него оформляется свидетельство.
- **Представитель заинтересованного лица** — по доверенности / договору.

**Тип обращения:**

- Обращение впервые;
- Корректировка материалов, по которым ранее получены замечания;
- Корректировка ранее одобренных материалов в целях внесения изменений в свидетельство АГР.

Повторная подача после замечаний — **всегда новое заявление** с типом корректировки, не правка старой карточки. См. [замечания-и-корректировка](замечания-и-корректировка.md).

## Сведения о проекте (важное для менеджера)

- **Источник ТЭП:** ГЗК / ГПЗУ / ППТ и т.п. Если есть и РГ ГЗК, и ГЗК — указывают **ГЗК** (с пунктом протокола).
- **УИН / адрес:** объекты, где организация — застройщик в цифровом паспорте. Нет в списке → «Проект не найден» + ручной ввод или `grad@mos.ru`.
- **GEOJSON МСК-77** — контур территории; при нескольких объектах — отдельный контур на каждый.
- Кадастровый / условный номер ЗУ, площадь, ВРИ, параметры объекта, машино-места, плановый срок.

## Загрузка на этапе ВПМ (типовой наш кейс)

Обязательно (по статье):

- ВПМ ZIP + `.sig` (имя подписи = имя ZIP);
- НПМ ZIP + `.sig`;
- URL результата проверки чекером IFC (`cimcheck` в ЛК).

Опционально: иные PDF, до 5 файлов, до 100 МБ каждый.

Буклет, презентация, транспорт и прочее система запрашивает по виду материалов — их готовит заказчик/проектировщик, не моделисты. См. [исходные-данные](../concepts/исходные-данные.md), [роль-команды](../team/роль-команды.md).

## Подпись архивов

У каждого ZIP — файл подписи с тем же именем. Подписать может руководитель, ИП, уполномоченное лицо или организация, подготовившая модели. Чью ЭП ставим на договоре — фиксируем отдельно.
